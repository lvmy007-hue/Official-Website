# 13 部署专项（暂缓）

> 状态：2026 年 10 月 21 日确认暂缓，待你确认后启动。暂缓期间，代码层的全部适配与降级按 14 章 14.10 执行；本章内容在启动时原样执行，不做删减。

## 13.1 目标

1. 业务应用部署到海外节点：贴近亚马逊接口，同时保证国内团队访问流畅。
2. 数据库、缓存、对象存储改为托管、高可用、加密、可恢复。
3. 建立亚马逊消息推送与营销数据流第二版的接收层，启用今日实时、今日广告、近实时预警。
4. 满足亚马逊数据保护政策中与部署相关的要求。
5. 官网保持现状，不迁移、不改动。

## 13.2 推荐拓扑

| 层 | 位置 | 理由 |
|---|---|---|
| 主应用区：网关、接口服务、后台任务进程、数据库、缓存、对象存储 | 阿里云香港 | 国内访问延迟低、无需备案、沿用现有阿里云账号；访问美国亚马逊接口的延迟可以接受 |
| 接收层：卖家接口推送的消息队列、营销数据流的存储桶与消息队列 | 亚马逊云美国东部（`us-east-1`） | 亚马逊在北美区域的推送与营销数据流投递，都要求使用亚马逊云的消息队列与存储桶 |

主应用区的后台任务进程通过加密连接，跨区拉取接收层的消息与文件。

**备选方案**：全部部署在亚马逊云美国东部。离亚马逊接口最近，但国内访问需要额外的加速服务。

## 13.3 组件清单

| 组件 | 部署方式 |
|---|---|
| 网关 | 负载均衡、网页应用防火墙、证书托管与自动续期 |
| 前端静态资源 | 对象存储加加速分发；资源文件名带哈希，长期缓存 |
| 接口服务 | 至少 2 个实例，无状态，按负载自动扩缩 |
| 后台任务进程 | 分 5 组部署：同步、报告解析、派生计算、导出、推送处理；每组独立扩缩，并设内存上限 |
| 数据库 | 托管 PostgreSQL，主备跨可用区；自动备份并支持按时间点恢复，备份保留 7 至 35 天；1 个只读副本供分析查询；前置连接池中间件；开启磁盘加密与连接加密 |
| 缓存 | 两个托管 Redis 实例：队列实例配置为"不淘汰"并开启持久化；缓存实例配置为"淘汰最久未用"；两者都启用密码与连接加密 |
| 对象存储 | 阿里云对象存储（香港）；按"租户 / 数据域 / 日期"组织路径；开启服务端加密；用生命周期规则把原始报告转低频存储，并按保留策略删除 |
| 接收层（美国东部） | 卖家接口推送队列及其死信队列；营销数据流按亚马逊官方模板创建存储桶与消息队列；加密密钥；给我方后台任务进程的最小权限读取角色 |
| 邮件发送 | 企业邮件服务，用于邀请、经营日报、告警；发信域名配置防伪认证记录 |
| 密钥管理 | 云密钥管理服务；生产环境不再用明文环境变量存放密钥，改为运行时注入 |
| 监控告警 | 指标、集中日志、链路追踪、可用性探测；告警发往邮件、飞书或企业微信 |

## 13.4 环境

开发、测试、预发布、生产四套环境相互隔离：

- 测试环境中有测试租户，使用官方格式的样例文件；
- 生产数据不进入测试与开发环境；
- 预发布环境的配置与生产一致，用于发布前验证。

## 13.5 发布流程

1. 持续集成依次执行类型检查、测试、构建、漏洞扫描。
2. 构建镜像并标记版本。
3. 在预发布环境自动部署并做冒烟验证。
4. 生产环境滚动发布。
5. 数据库迁移先于应用发布执行，并保持向后兼容。
6. 支持一键回滚到上一版本。

## 13.6 从现有单机迁移的步骤

1. **网络**：开通账号，建立私有网络、子网、安全组；只有网关暴露在公网。
2. **托管数据服务**：创建托管数据库与两个 Redis 实例，开启加密与备份。
3. **接收层**：
   - 在美国东部建好推送队列、营销数据流存储桶与队列；
   - 在卖家接口登记推送目的地并创建订阅；
   - 创建营销数据流订阅，订阅后亚马逊会回补 70 天数据。
4. **应用部署**：应用容器部署到新环境，接入密钥管理。
5. **数据迁移**：选择以下两种方式之一。
   - 停写窗口：导出后导入，核对行数与校验和；
   - 逻辑复制：持续同步数据，切换时只需短暂停写。
6. **切换**：切换访问域名的解析，观察运行情况；旧环境保留 7 天以备回滚。
7. **下线**：确认稳定后关闭旧的单机部署。

## 13.8 合规核查清单（亚马逊数据保护政策中与部署相关的部分）

1. 传输与存储全部加密，备份也加密。
2. 最小权限访问；生产访问必须经过审批，并留存审计记录。
3. 日志集中留存，日志中不含买家个人信息。
4. 安全事件响应预案：按亚马逊要求的时限通知，并明确负责人与联系方式。
5. 买家个人信息保留期限按亚马逊当期政策配置，到期自动删除。
6. 记录每类数据的存放位置。
7. 每季度做一次漏洞扫描与恢复演练。

## 13.9 验收

1. 国内办公网络访问 ERP，首屏加载与接口响应满足 12 章 12.4 的预算。
2. 主动停掉任意一个接口服务实例或后台任务实例，业务不中断。
3. 能把数据库恢复到任意时间点，恢复演练通过。
4. 消息推送与营销数据流端到端通畅：今日实时、今日广告显示真实数据，并标注"实时估算"。
5. 内部链路全部加密；Redis 只允许内网访问且需要密码。
6. 密钥不以明文出现在任何配置文件或环境变量中。
7. 告警链路能正常送达。
