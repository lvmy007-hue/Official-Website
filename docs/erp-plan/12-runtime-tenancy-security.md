# 12 运行性能、租户与安全加固

本章回答：整体架构是否具备分页、流程可靠性、加载流畅性、内存溢出防护、可维护性、租户注册、租户数据隔离、传输防截取能力。先列现状核查结论，再给出补全方案。

## 12.1 现状核查（基于代码，2026 年 10 月 21 日）

| 项目 | 现状 | 风险 |
|---|---|---|
| 列表分页 | 偏移量分页，每页都重新统计总数 | 数据量大时越往后越慢，统计总数拖慢每一页 |
| 报告下载 | 整份文件读入内存，同步解压后转成字符串再解析 | 大报告（库存规划、结算、广告搜索词）会内存溢出，并阻塞后台任务进程 |
| 利润与词级下钻 | 先截取部分数据，再在内存汇总 | 结果被截断、内存占用随数据增长 |
| 前端加载 | `App.tsx` 184KB 同步加载，组件库整体引入，无路由级懒加载 | 首屏慢 |
| 任务流程 | 单队列、无死信、无断点续传、无写操作幂等键 | 失败后重复执行可能重复创建亚马逊侧对象 |
| 刷新令牌 | 30 天有效，使用后不轮换 | 被截取后可长期复用 |
| 真实客户端地址 | 接口服务未配置代理信任，位于网关之后 | 限流与登录锁定取到的都是网关地址，所有用户共用一个限流桶 |
| 内容安全策略 | 已关闭 | 跨站脚本防护弱 |
| 内部链路 | 数据库与 Redis 无传输加密，Redis 无密码 | 拆分部署后内部流量可被窃听 |
| 租户开通 | 商务订单激活时创建租户，默认时区上海、默认币种人民币 | 与美国站美元口径不一致；缺少初始化向导与邀请流程 |
| 租户隔离 | 每条查询手写租户条件，数据库层无兜底 | 一处遗漏即可越权 |

## 12.2 分页方案

| 类别 | 适用 | 做法 |
|---|---|---|
| 游标分页 | 海量表：订单、订单行、费用事件、财务交易、库存台账、广告指标、词级数据、审计日志 | 以"排序字段 + 编号"组成复合游标，服务端签名防篡改；游标绑定查询条件，条件变化即失效 |
| 页码分页 | 中小表：成员、角色、规则、供应商、采购单、连接 | 普通页码，总数精确统计 |
| 汇总接口 | 指标卡、图表、对比 | 不分页，读汇总表 |

**补充规则：**

1. **页大小**：默认 50，上限 200。AG Grid 无限滚动每块 100 行，前端最多缓存 10 块，超出后淘汰最早的块。
2. **总数**：海量表显示"约 N 条"，来源为汇总表计数或数据库统计估算；需要精确总数时，按需异步计算。
3. **排序**：只允许有索引支撑的字段（白名单），其他字段一律拒绝。
4. **跳页**：海量表不提供"跳到第 N 页"，改为按时间、编号等条件定位。
5. **导出**：不走分页，用服务端流式导出——数据库游标流式读取，流式写入文件，再上传对象存储。

## 12.3 运行流程可靠性

**统一状态机**

所有异步流程统一为"状态机 + 持久化步骤记录"，包括同步、报告、入仓多步操作、上游仓储操作、广告写入、分时与规则执行、导出、关账。每一步记录：状态、输入摘要、输出摘要、重试次数、下次执行时间、错误码。

**写操作幂等**

- 每个写请求携带幂等键，服务端在 24 小时内去重，重复提交返回同一个结果。
- 对亚马逊的写操作按三步走：先记录"待执行"意图，再调用亚马逊，最后记录结果。
- 进程崩溃后恢复时，先向亚马逊查询该对象的当前状态，再决定是否重试，避免重复创建入仓计划、广告等对象。

**重试与死信**

- 错误分两类：可重试（限流、超时、服务端错误）与不可重试（参数错误、权限不足）。
- 可重试错误按指数退避加随机抖动重试。
- 超过重试次数后进入死信队列并告警；同步中心可以手动重放。

**超时与心跳**

- 每类任务设定最长运行时间，运行期间持续上报心跳。
- 失去心跳的任务被自动回收并重新排队。

**并发控制**

- 同一店铺、同一数据域使用带租约的分布式锁，同一时间只跑一个任务。
- 对同一业务对象的写操作串行执行。

**补偿**

多步流程中途失败时，执行补偿动作。例如入仓计划在作废窗口内自动取消。

**优先级**

从高到低：用户触发、推送增量、定时任务、历史回补。

**断点续传**

大报告每解析完一批就提交并记录偏移位置；失败后从断点继续，不从头开始。

**优雅停机**

收到停止信号后不再领取新任务，当前批次完成或断点保存后才退出。

**进度可见**

同步中心展示每个任务的分步进度。

## 12.4 加载与打开流畅性

### 前端

1. **路由级代码分割**：每个页面独立懒加载，首屏只加载外壳和当前页面。
2. **首屏体积预算**：外壳加首页的脚本，压缩后不超过 350KB（CR-096 由 300KB 放宽）。图表库与 AG Grid 按需加载，Ant Design 按需引入。
3. **预加载**：鼠标悬停在导航项上时，提前加载对应页面的代码与数据。
4. **数据缓存**：
   - 按数据域设定缓存新鲜时间，例如控制台 60 秒、主数据 10 分钟；
   - 返回上一页时立即显示缓存，同时在后台刷新。
5. **渐进渲染**：先渲染身份区与指标卡；页签内容在切换时才加载；首屏以下的图表进入视口后再渲染。
6. **虚拟滚动**：所有海量表格、长列表、时间线。
7. **图表**：
   - 数据点超过 2000 个时，由服务端按时间桶降采样；
   - 大数据量开启渐进渲染；
   - 离开页面时销毁图表实例。
8. **静态资源**：文件名带哈希，长期缓存；压缩传输；就近加速（见 13 章）。
9. **性能监控**：采集首次可交互时间、最大内容渲染时间、接口耗时。采集数据不含任何个人信息。

### 后端

1. **响应时间预算**：汇总接口第 95 百分位不超过 300 毫秒；列表与详情第 95 百分位不超过 500 毫秒。
2. **读汇总表**：页面读汇总表，不实时扫描明细表。
3. **慢查询**：
   - 超过 1 秒的查询记录日志并告警；
   - 新增查询必须经过索引评审；
   - 数据库语句超时设为 10 秒。
4. **热点缓存**：热点汇总做短时缓存，写操作或同步完成时按键失效；缓存键包含租户与范围。
5. **响应精简**：响应压缩，字段裁剪，只返回页面需要的字段。
6. **连接池中间件**：避免多实例把数据库连接打满。

## 12.5 内存溢出防护

### 后台任务进程

1. **报告处理改为流式**：下载流 → 解压流 → 逐行解析 → 每 1000 行一批写库。原始文件同时以流的方式写入对象存储。常驻内存与文件大小无关。
2. **其他大文件同样流式读取**：数据中心查询结果、营销数据流文件。
3. **禁止的写法**：同步解压、整份文件转字符串、一次性把查询结果全部读入内存。
4. **批量写入**：分批提交，并限制单个事务的大小。
5. **进程上限**：
   - 每个进程设置堆内存上限；
   - 常驻内存超过阈值时，停止领取新任务，处理完当前任务后自动重启；
   - 并发数按内存预算设定。
6. **队列消息**：只存编号和参数，大对象放对象存储。

### 接口服务

1. **请求体上限**：默认 1MB。附件上传使用对象存储签名地址，由浏览器直传。
2. **查询必须有边界**：任何查询都要带分页或聚合；运行时检测到超过上限行数的查询直接报错，代码审查中同样检查。
3. **导出**：一律流式处理。
4. **内存泄漏监控**：定期对比堆快照；检查定时器与事件监听是否已清理。

### 前端

1. 表格虚拟化，图表降采样。
2. 页面卸载时销毁图表实例与订阅。
3. 数据缓存设定上限与回收时间。
4. 长时间打开的页面（大屏、今日实时）定时刷新时替换数据，不累加。

## 12.6 可维护性

1. **模块边界**：
   - 后端每个领域模块独立目录，包含控制器、服务、查询、校验、测试；跨模块只能调用公开服务；
   - 前端每个业务模块独立目录，共享组件只放在共享目录。
2. **契约优先**：前后端共用同一份校验定义生成类型；接口变更必须同步更新契约与测试。
3. **数据库迁移**：
   - 每次迁移写明回滚方法；
   - 大表变更采用"先加后删"的兼容步骤，避免长时间锁表。
4. **功能开关**：新功能与接口迁移通过开关灰度发布。
5. **版本化**：接口路径带版本；口径、规则、策略都有版本号。
6. **文档同步**：每个模块的说明（数据来源、口径、权限）与指标口径字典保持同步。
7. **代码规范**：
   - 统一代码格式化与静态检查；
   - 单个文件不超过 400 行；
   - 禁止超长单行；
   - 统一命名规范。
8. **依赖管理**：定期升级，并做漏洞扫描。
9. **可观测性**：
   - 结构化日志带请求编号与租户编号，不含个人信息；
   - 链路追踪贯穿接口、队列、后台任务。
10. **运维手册**：覆盖授权失效、限流、报告失败、推送中断、队列积压的处理步骤。

## 12.7 租户注册与生命周期

**原则**：采用报价制，不提供在线支付，不开放公开自助注册，以防止滥用和数据风险。

**开通流程**

1. **线索**：官网联系表单（已有）提交的线索进入平台运营后台。
2. **开通**：平台管理员在平台运营后台创建租户，或在报价确认后激活商务订单（已有能力）。需填写企业名称、标识、首个管理员邮箱。
3. **邀请**：
   - 系统给首个管理员发送一次性邀请链接，有效期 72 小时，只能使用一次，服务端只存令牌的哈希值；
   - 首个管理员设置密码，并强制开启多因素认证。
4. **初始化向导**（租户内完成，进度可保存；未完成前页面显示"未完成企业初始化"）：
   1. 企业资料：数据口径时区默认美国太平洋时区，显示币种默认美元（修正当前默认上海时区与人民币的问题）；另设企业本地时区，用于日报发送时间；
   2. 法律主体；
   3. 卖家接口授权（店铺）；
   4. 广告接口授权，以及广告账户与店铺的绑定；
   5. 同步范围与历史回补时长；
   6. 汇率与成本口径；
   7. 邀请成员并分配角色与数据范围；
   8. 写入开关：默认全部只读。
5. **首次同步**：历史回补任务分段执行。例如财务交易按接口限制每段最多 180 天，广告报表每段最多 120 天。进度可见。

**生命周期**

| 状态 | 含义 |
|---|---|
| 正常 | 完整使用 |
| 暂停 | 只读，停止同步 |
| 停用 | 停止访问，数据保留设定天数 |
| 注销 | 依次执行：导出数据交付给客户、撤销亚马逊授权、删除令牌、删除买家个人信息、按保留策略删除业务数据、生成删除证明 |

**平台运营后台**（新增，与租户内的 ERP 完全分离）：
- 租户列表、开通、暂停、停用；
- 用量统计：店铺数、成员数、数据量、同步任务量；
- 支持访问：必须经租户授权、限定时长、全程审计。

**防滥用**：邀请与登录限流、邮箱验证、密码强度要求、登录失败锁定（已有）、新设备登录提醒。

**配额**：按报价开通的能力与配额（店铺数、成员数、历史回补长度）记录在租户设置中，超出时提示。不做在线支付。

## 12.8 租户数据隔离（多层防线）

1. **应用层**：所有查询经过统一的数据访问层，自动为租户表注入租户条件。禁止绕过数据访问层直接查询；用静态检查规则拦截不带租户条件的查询。
2. **数据库层**：启用 PostgreSQL 行级安全策略作为第二道防线。
   - 每个请求事务开始时设置当前租户变量，策略只放行该租户的数据行；
   - 接口服务使用非超级用户账号连接数据库；
   - 迁移与运维使用单独的账号。
3. **范围层**：租户内部再按主体、店铺做数据范围过滤。
4. **缓存**：缓存键一律以租户编号开头；前端切换租户时清空本地缓存。
5. **队列与后台任务**：
   - 任务只携带租户编号与对象编号；
   - 执行时重新加载对象并校验其归属租户；
   - 后台任务同样设置租户变量，受行级安全策略约束。
6. **对象存储**：
   - 路径按"租户 / 数据域 / 日期"组织；
   - 只能通过服务端签发的短时签名链接访问，无法跨租户枚举文件。
7. **导出与搜索**：同样经过统一数据访问层。
8. **日志**：带租户编号，但不含业务敏感数据。
9. **编号防枚举**：对外暴露的编号不可猜测；每次按编号访问都校验归属，不属于当前租户的一律返回"不存在"。
10. **越权测试**：用租户甲的身份访问租户乙的每一类对象，期望返回拒绝或不存在。该测试纳入持续集成。
11. **独立数据库（可选）**：大客户可使用独立数据库，代码不变，按租户路由到对应的库。

## 12.9 传输与防截取安全

**结论**

- 浏览器到服务端已启用加密传输（TLS 1.2 与 1.3，并开启强制加密），正常情况下数据在传输途中无法被读取或篡改。
- 但现状仍有缺口：内部链路未加密、Redis 无密码、内容安全策略关闭、刷新令牌不轮换、取不到真实客户端地址。

**补全方案**

1. **浏览器到服务端**：
   - 强制加密，只允许 TLS 1.2 与 1.3，禁用不安全的加密套件；
   - 强制加密策略加入浏览器预加载列表；
   - 证书自动续期，并做证书透明度监控。
2. **服务端内部**：
   - 接口服务与后台任务进程到数据库、Redis、对象存储的连接全部启用加密，数据库强制加密连接并校验证书；
   - Redis 启用密码与访问控制，只允许内网访问；
   - 所有服务部署在私有网络，只有网关暴露在公网。
3. **到亚马逊**：
   - 所有接口调用走加密传输，并校验证书，任何情况下都不关闭证书校验；
   - 报告下载地址是亚马逊签发的短时链接，不写入日志。
4. **消息推送与营销数据流的接收**：
   - 队列与存储桶通过资源策略限定：只允许亚马逊的发布角色写入，只允许我方的读取角色读取；
   - 开启服务端加密；
   - 我方拉取走加密传输，并校验消息来源。
5. **令牌**：
   - 访问令牌有效期 15 分钟（保持现状），只放在内存中；
   - 刷新令牌每用一次就换新；一旦发现旧刷新令牌被再次使用，立即吊销该会话的全部令牌并告警——即使令牌在途中被截取，也无法长期冒用；
   - 刷新凭据只允许服务端读取、只在加密连接上发送，并启用严格的同站限制；
   - 用户可以在个人账号中逐个注销会话。
6. **防重放与高风险操作**：
   - 所有写操作必须携带幂等键；
   - 以下高风险操作要求近期重新验证身份（密码或多因素认证），并记录在审计中：开关写入、修改价格、广告批量修改、关账、成员权限变更、导出敏感数据。
7. **跨站防护**：
   - 开启内容安全策略，只允许本站脚本与白名单域名；
   - 禁止页面被其他站点嵌入；
   - 跨域请求只允许白名单来源；
   - 刷新接口校验请求来源。
8. **数据最小化**：
   - 接口只返回页面需要的字段；
   - 买家信息默认不返回，令牌永不返回；
   - 错误信息不泄露内部细节。
9. **真实客户端地址**：配置代理信任，只信任我方网关，修复限流与登录锁定拿不到真实地址的问题。
10. **静态加密**：
    - 数据库磁盘、对象存储、备份全部加密；
    - 令牌与买家信息在应用层再加密一次。
11. **边界防护**：网关层部署网页应用防火墙、拒绝服务攻击防护和异常流量限流。
12. **多因素认证**：管理员强制开启，其他成员可选。
