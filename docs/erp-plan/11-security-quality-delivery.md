# 11 安全、质量与实施

## 11.1 权限

- **格式**：统一为"模块.动作"，例如 `orders.read`、`pricing.price.write`、`listing.write`、`reviews.solicit`、`aplus.write`、`inbound.plan.write`、`awd.order.write`、`purchase.order.approve`、`replenishment.plan.create`、`finance.reconcile`、`finance.period.close`、`profit.read`、`ads.campaign.write`、`ads.bid.write`、`ads.negative.write`、`ads.rule.write`、`alerts.manage`、`workitem.assign`、`settings.integration.write`、`settings.fx.write`、`export.create`、`audit.read`、`data.import`（文件导入：评分与评分数、仓储限额、货代节点）。现有 16 个旧权限通过映射表继续生效。
- **数据范围**：成员可被授权为全部主体、指定主体或指定店铺。后端每次查询都与请求参数取交集，交集为空时拒绝访问。广告数据通过"广告账户绑定的店铺"参与过滤。
- **字段级敏感权限**：采购成本、利润、买家信息单独授权。没有授权时，这些字段在页面、导出、接口响应中一律不出现。
- **站点白名单**：只允许美国站，配置在后端。

## 11.2 安全

1. 访问令牌只存在内存；刷新凭据放在只能由服务端读取的浏览器凭据中；刷新接口校验请求来源，防止跨站请求伪造。
2. 亚马逊令牌加密存储，采用"主密钥加密数据密钥"的方式，支持密钥轮换。令牌永不返回前端，也永不写入日志。
3. 买家个人信息加密存储、到期删除。访问需要角色授权并填写理由，每次访问写审计。买家个人信息不进入导出、日志和智能问答。
4. 所有写操作写审计，记录修改前后的差异、请求编号、来源地址、访问模式。
5. 导出文件、附件、原始报告的下载链接全部签名，且短时有效。上传附件校验文件类型与大小。
6. 按用户与租户限流。
7. 持续集成中做依赖漏洞扫描。
8. 对照亚马逊数据保护政策逐条核查。其中数据存放位置的部分在部署专项中完成。

## 11.3 内部访问模式

- 部署配置项：
  - `INTERNAL_DIRECT_ACCESS`：默认关闭；
  - `INTERNAL_ACCESS_TENANT_ID`：绑定的固定内部租户；
  - `INTERNAL_ACCESS_ROLE_ID`：绑定的最小权限角色，默认只读；
  - `INTERNAL_ACCESS_ALLOWED_CIDRS`：允许访问的内网地址段；
  - 可选：内网网关注入的校验头。
- 后端校验来源地址，前提是代理信任配置正确。
- 生产环境开启时，启动日志输出告警。
- 页面顶部显示"内部访问模式"横幅；审计记录中标注访问模式与来源地址。
- 现有本地免登录只在开发环境可用；普通生产模式继续走现有登录。

## 11.4 质量与可观测性

- **测试**：
  - 接口用测试数据库做集成测试；
  - 导入器用亚马逊官方格式的样例文件测试，并验证重复导入不产生重复数据；
  - 利润计算、汇率回退、广告分摊、补货计算、范围权限、乐观锁、写入开关、动作守卫做单元测试；
  - 前端关键组件做测试。
- **测试租户**：仅测试环境存在，加载官方格式样例文件，走真实的导入与计算链路。生产租户在代码层拒绝加载样例文件。
- **代码规范**：代码格式化与静态检查；禁止超长单行；限制单文件行数；禁止跨模块越界引用。
- **持续集成**：类型检查、测试、构建、漏洞扫描全部通过才允许合并。
- **可观测性**：统一结构化日志与指标。以下情况告警：同步失败、授权即将失效、写入开关被自动关闭、汇率获取失败、推送中断、队列积压。

## 11.6 全站验收标准

1. 页面中不出现"规划中""演示数据""示例记录"，也不出现写死的日期或数字。
2. 不存在用一个通用表格页承载多个业务域的情况。
3. 顶部切换主体、店铺、站点、时间范围后，列表、图表、详情、导出使用同一个真实数据范围。
4. 每个一级模块至少具备：正式列表或工作台、业务化详情页、空态、错误态、加载态、权限态、资格态。
5. 页面中不混入自发货语义；没有真实来源的字段不显示，或者明确标注来源为"文件导入"。
6. 每个图表、指标、风险提示都能追溯到接口、报告、推送或同步任务。
7. 每个按钮要么真实可用，要么因权限、连接、写入开关或数据条件明确禁用；不存在用前端提示假装成功的情况。
8. 保持现有可部署的全栈结构；类型检查、测试、构建全部通过；核心接口、计算逻辑、权限有测试覆盖。
9. Arco 依赖、手写组件样式、旧样式文件全部删除。
10. 所有趋势图支持事件标注；所有核心数字支持可追溯；关键数字具备双源核对。
11. 所有估算类结果标注"模型估算"并说明方法。
12. 美国站入仓流程不出现由亚马逊预处理或贴标的选项。
