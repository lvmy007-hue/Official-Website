# P0-06 指标口径字典（冻结稿，初稿待你确认）

依据：03 章 3.2；04 至 09 章所有页面出现的指标；`importers.md`（来源）；`models.md`（落点）。
用途：实施阶段的"指标口径页"（`/app/help/metrics`，P1-28 第 8 项）以本字典为数据源；每个页面的指标卡、表格列、图表都必须在本字典中有条目，**同名指标在同一企业、同一时刻只有一个生效口径**（阶段 6 起，利润公式与业务口径允许企业配置，但生效版本唯一、每个数字带口径版本号，见第十节 10.6）。

## 零、总规则

### 0.1 类型标注（README 术语约定）

| 类型 | 含义 | 页面标注 |
|---|---|---|
| 官方 | 直接取自亚马逊接口、报告、数据集，我方不重算 | 无需特别标注，悬停显示来源 |
| 我方计算 | 由我方按公式从已落库数据确定性计算 | "我方计算" |
| 模型估算 | 含预测、外推、基线假设，结果有不确定性 | "估算"，并显示方法与区间 |
| 导入 | 来自卖家授权的文件导入 | 标注来源、采集日期 |

### 0.2 口径约束

1. **同名同义**：同一名称只对应本字典一条定义。口径不同的指标必须用不同名称，例如"广告转化率"与"单位会话转化率"、"订单净收益"与"官方净收益"；
2. **时区与日界**：所有"日"按企业设置的数据口径时区切分，默认美国太平洋时区；广告指标按广告账户时区，与店铺时区不同时在页面角标提示；
3. **币种**：金额一律显示原币金额、折算金额、汇率、汇率来源，不允许跨币种直接相加；显示币种默认美元；
4. **分母为零**：比率类指标分母为零时显示"—"，不显示 0%，也不显示无穷；
5. **缺数据**：任一必需输入缺失（如无成本、无汇率）时，该指标显示"数据不全"并说明缺哪项，不用 0 代替；
6. **口径版本**：每条指标有口径版本号 `@n`，初始均为 `@1`；公式、来源、时区规则任一变化即升版本，旧版本保留并在指标口径页展示变更历史；关账期间的数据按关账时的口径版本冻结；
7. **刷新频率**：写明"数据最快多久更新一次"，页面数据新鲜度条据此判断延迟；
8. **归因窗口**：广告销售按亚马逊 `Reporting API v1` 的流量日期归因，近 3 天会被回补修正（见 `importers.md` A-02）。

### 0.3 本字典新增的口径决定

06 章、07 章对下列指标只给出名称，没有给出公式或参数。本字典按下表补全，**这是新增的口径决定，已于 2026-10-21 经你确认**，同步写入 09 章 9.5。

| 编号 | 指标 | 本字典补全的内容 | 理由 |
|---|---|---|---|
| D-02 | 刊登质量分 | 0 至 100 分；权重：属性完整度 40、图片数量与规格 20、五点描述条数 15、A+ 状态 10、问题数扣分 15 | 05 章列出五个要素，未给权重 |
| D-03 | 指标树归因算法 | 采用对数平均迪氏分解（LMDI），保证三个因子的贡献之和严格等于总变化 | 04 章要求"拆为三项贡献"，未指定算法；简单差分会留下无法分配的交叉项 |
| D-04 | 平均超预算时长 | 活动日预算在当日耗尽的时刻起，至该日结束的小时数，取所选期间的日均值 | 08 章列为指标，未定义 |
| D-05 | 价格弹性估算 | 最近 180 天、剔除促销日与断货日，日销量对价格做对数回归；有效日不足 30 天或价格变化点少于 3 个时不显示 | 05 章要求"基于历史数据的弹性估算"，未定义方法 |
| D-06 | 促销增量基线 | 基线为活动开始前 28 天内，未参加其他促销的天数的日均值，按星期对齐 | 04 章要求"基线法"，未定义窗口 |
| D-07 | 成本覆盖率 | 按销售额加权：有生效成本版本的 SKU 的销售额 ÷ 全部销售额 | 07 章关账检查提到"达标"，未定义分子分母 |

### 10.6 可配置口径与“同名同义”的关系（CR-096 放开，CR-107 登记）

第零节 0.2 第 1 条“同名同义”不变，在阶段 6 作如下限定：

1. **同一企业、同一时刻、同一名称只有一个生效口径**。利润公式、业务口径、利润项目字典、费用分摊规则允许企业配置，但全站所有页面读同一个生效版本，不允许不同页面用不同公式；
2. 配置修改形成新的**口径版本**（`MetricVersion`，P6-18 建表、P6-31 接入），与第零节 0.2 第 6 条的指标口径版本 `@n` 是两件事：`@n` 是字典里公式本身的变更，**口径版本**是企业对可配置项的选择；
3. 每个受配置影响的数字都带口径版本号：问号显示当前公式与版本，导出文件表头写明版本，关账快照记录当时的版本；已关账月份不受之后的修改影响，需要按新口径重算时生成差异报告，不改动快照；
4. 字典里这类条目由 `configurableAt` 标明在哪里配置。

### 10.8 可用于规则条件的指标（P6-07 落地，由生成脚本合并进 `/metrics/definitions` 的 `ruleUse`）

规则条件构造器（预警、调价、自动规则共用，契约 `rule-conditions.ts`）只能选这里登记的指标；没有登记的指标 `ruleUse` 是 `null`，`GET /metrics/definitions?ruleUsable=true` 只返回登记过的。**格式**：表头必须是 `| 编号 | 指标 | 规则域 | 数值单位 | 聚合方式 |`；规则域取 销售、广告、库存、利润、售后（对应 `sales`、`ads`、`inventory`、`profit`、`aftersales`）；数值单位取 金额、百分比、件数、天数、倍数（对应 `money`、`percent`、`count`、`days`、`ratio`）；聚合方式用 `、` 隔开，取 合计、平均值、最新值、最小值、最大值。**约定**：百分比类指标在规则里一律用百分数（35 就是 35%）；比率、存量、天数类指标不能“合计”；库存类是存量，只有最新值、平均值、最小值、最大值。生成脚本校验：编号必须在主表里、不得重复、域与单位与聚合方式必须是上面的取值。新增指标要上规则，先在这里登记，再补对应的取数实现（P6-15、P6-16）。
