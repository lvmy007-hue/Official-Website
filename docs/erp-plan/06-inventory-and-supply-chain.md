# 06 板块详设：库存与供应链

---

## 6.1 库存健康 `/app/inventory`

**定位**：亚马逊物流库存的健康工作台。字段基于亚马逊物流库存接口（实时数量）与库存规划报告（健康与费用）。

**对标与超越**：头部 ERP 提供库存报表、缺货看板、库龄。本页增加：
- 我方规则与亚马逊官方健康状态、官方建议动作并列；
- 低库存水平费风险；
- 库龄附加费的跨档日期预警；
- 季节性标记；
- 预测区间。

**7 个页签**：全部库存、低库存（含低库存水平费风险）、冗余、库龄风险、滞留、不可售、在途。

**指标卡**：可售总量、在途总量、不可售总量、低库存 SKU 数、冗余 SKU 数、预计下月仓储费、预计库龄附加费、低库存水平费风险 SKU 数。

**图表**：库存结构堆叠图、库龄分段分布、可售天数分布、费用趋势。

**表格字段**：

| 分组 | 字段 |
|---|---|
| 商品 | 图片、ASIN、SKU、FNSKU、负责人 |
| 数量 | 可售；预留（客户订单、仓内处理、中转）；在途（处理中、已发货、接收中）；不可售；调查中；上游仓储库存 |
| 销售 | 近 7、30、60、90 天销量；预测日销（低、中、高） |
| 覆盖 | 我方可售天数、亚马逊历史可售天数（短期、长期）、目标库存天数、周覆盖、售罄率 |
| 库龄 | 0-30、31-60、61-90、91-180、181-270、271-365、366-455、456 天以上 |
| 费用 | 预计下月仓储费、库龄附加费各分段预估、长期仓储费预估、低库存水平费（是否收取、是否豁免）、亚马逊最低库存水平 |
| 季节性 | 未来 3 个月是否季节性、季节名称、起止日期 |
| 状态 | 滞留原因、我方健康状态、亚马逊库存健康状态 |
| 建议 | 我方建议动作；亚马逊建议动作（建议售价、建议促销天数、建议移除数量、预计节省） |

**健康规则**（规则带版本，不使用固定阈值）：

1. 可售天数 =（可售 + 计入的在途）÷ 预测日销。
2. 预计断货日 = 今天 + 可售天数。
3. 风险等级：
   - **高**：断货日早于最快补货到仓日。最快补货到仓日按"采购 + 国内运输 + 头程 + 入仓接收"计算，或按"上游仓储调拨到亚马逊物流"的时效计算，取两者中更快的一个。
   - **中**：断货日在安全库存覆盖范围内。
   - **冗余**：库存覆盖超过目标天数的设定倍数。
4. 安全库存、提前期、目标天数均来自补货策略（见 6.2）。

**库存详情** `/app/inventory/:id`

- **身份区**：商品信息、我方健康状态、亚马逊健康状态、可售天数、预计断货日、目标天数、最快补货到仓日。
- **10 个页签**：
  1. 库存结构趋势：各数量分项的堆叠趋势。
  2. 历史快照：任选两个日期对比。
  3. 库存台账：该 SKU 的流水，可跳转到对应单据。
  4. 入仓与在途：货件列表、预计到仓时间、接收进度。
  5. 上游仓储：在库数量、发往亚马逊物流的在途。
  6. 补货建议：我方建议与亚马逊官方建议并列，并说明差异原因。
  7. 库龄与费用：
     - 库龄分段柱状图；
     - 库龄附加费跨档时间线：标出哪些数量将在哪一天进入下一档、预计费用增加多少。
  8. 处置建议：移除、降价促销、建议售价，同时列出官方建议与我方建议，以及各自的预计节省。
  9. 预测：日销预测图（带区间），并说明季节标记、促销期与断货期是否被剔除。
  10. 变更与审计。

**数据来源**：`FBA Inventory API v1`、`GET_FBA_INVENTORY_PLANNING_DATA`、`GET_RESERVED_INVENTORY_DATA`、`GET_STRANDED_INVENTORY_UI_DATA`、`GET_LEDGER_DETAIL_VIEW_DATA`、`GET_FBA_STORAGE_FEE_CHARGES_DATA`、`GET_RESTOCK_INVENTORY_RECOMMENDATIONS_REPORT`、亚马逊仓储分销接口；推送 `FBA_INVENTORY_AVAILABILITY_CHANGES`、`ITEM_INVENTORY_EVENT_CHANGE`。

## 6.2 补货建议 `/app/replenishment`

**定位**：以"建议批次"给出可执行的补货计划，每个数字都能展开计算过程。

**对标与超越**：头部 ERP 已有近 90 天销量、季节性、剔除异常、按运输方式拆分、连续补货计划、库存走势试算。本页增加：
- 与亚马逊官方补货建议做双源核对；
- 把订阅省的确定性需求纳入预测；
- 上游仓储供给纳入计算；
- 按"总到仓成本"而不只是运费选择运输方式；
- 每条建议执行后回看结果，评估建议质量。

**计算链**（每一步都可展开）：

1. **需求预测**：历史销量剔除断货期与异常值，叠加季节性、促销计划、订阅省预计出货、趋势，输出低、中、高三个区间。
2. **供给**：可售 + 亚马逊物流在途 + 上游仓储在库与在途 + 国内仓可用 + 采购在途。
3. **提前期**：生产、国内运输、头程（按运输方式，取自头程时效统计的实测值）、入仓接收、上游仓储调拨到亚马逊物流。
4. **安全库存**：由服务水平、需求波动、提前期共同决定。
5. **目标覆盖**：取补货策略中的目标天数。
6. **建议量**：按箱规与最小起订量取整。
7. **运输方式拆分**：比较海运、空运、快递的时效与成本，按总到仓成本与断货风险分配数量。
8. **时间**：得出建议发货日、预计到仓日。

**列表**（按批次分组，一个 SKU 可能有多批，覆盖未来若干周）：

| 字段 | 说明 |
|---|---|
| SKU、当前可售、预测日销（区间） | — |
| 预计断货日、目标覆盖天数 | — |
| 建议补货量、建议采购数量 | 已按箱规与最小起订量取整 |
| 建议发货日、建议运输方式、预计到仓日 | — |
| 资金占用 | 按成本版本计算 |
| 风险等级 | — |
| 亚马逊官方建议量、差异原因 | 双源核对 |
| 公式展开 | 计算过程与数据时间 |

**策略编辑**：安全库存、各段提前期、服务水平、目标天数、运输方式偏好、箱规、最小起订量。可在企业、品类、SKU 三级设置，下级覆盖上级。修改后重算，带版本号。

**模拟**：
- 库存走势模拟图：未来 90 天，分"不补货""按建议补货""自定义"三条曲线，断货区间标红；
- 发往上游仓储的情景：调用单品经济模拟，输入发往上游仓储的数量，看费用与净收益变化。

**动作**（多选）：
- 生成采购单草稿；
- 生成入仓计划草稿；
- 生成上游仓储入库订单草稿。

**批次详情** `/app/replenishment/batches/:id`：
- 批次内的 SKU；
- 计算快照：冻结生成当时的全部输入；
- 执行情况：转成了哪些采购单、入仓计划；
- 结果回看：是否按时到仓、是否发生断货、预测误差。回看结果用于评估与改进补货模型。

## 6.3 亚马逊仓储分销 `/app/awd`

**定位**：管理美国站上游仓储的库存与入库。

**3 个页签**：
1. **库存**：在库、可分配、补货订单预留、有效期、发往上游仓储在途、上游仓储发往亚马逊物流在途。
2. **入库订单**。
3. **入库货件**。

**入库订单详情** `/app/awd/orders/:id`：
- 包裹与内容；
- 发货地址、区域偏好；
- 货件列表；
- 箱标签；
- 运输信息；
- 状态时间线；
- 按 SKU 的预期数量、接收数量、有效期、预处理信息。

**动作**：创建、更新、取消、确认入库订单；获取箱标签；更新运输信息。全部受写入开关控制，写审计。

**联动**：上游仓储在库与在途数量纳入补货计算。

**数据来源**：`Amazon Warehousing and Distribution API v2024-05-09`。

## 6.4 库存台账 `/app/inventory/ledger`

**事件类型**：接收、客户发货、客户退货、供应商退货、移除、调整（丢失、损坏、找到、处置）、仓间转运、其他。

**两种视图**：
- **汇总**：按 SKU × 月，列出期初、接收、发货、退货、调整、期末；
- **明细**：逐条流水，可跳转到来源单据。

**先进能力**：
- 平衡校验："期初 + 变动 = 期末"，不平的行标红；
- 与实时库存接口的数量比对；
- 丢失与损坏自动生成赔付机会（见 07 章）。

**数据来源**：`GET_LEDGER_SUMMARY_VIEW_DATA`、`GET_LEDGER_DETAIL_VIEW_DATA`。

## 6.6 仓储容量与费用 `/app/inventory/capacity`

**内容**：
- 仓储利用率及利用率附加费；
- 超出仓储限额费；
- 按仓储类型的体积使用；
- 仓储限额：有官方来源时直接接入，否则用卖家后台导出文件导入，并标注来源。

**费用趋势**：月度仓储费、库龄附加费、长期仓储费、低库存水平费。

**预测**：下月仓储费、库龄附加费跨档提醒。

**优化建议**：列出占用体积大但周转慢的 SKU，并给出建议动作。

**数据来源**：`GET_FBA_STORAGE_FEE_CHARGES_DATA`（含 `storage_utilization_ratio`、利用率附加费字段）、`GET_FBA_OVERAGE_FEE_CHARGES_DATA`、`GET_FBA_FULFILLMENT_LONGTERM_STORAGE_FEE_CHARGES_DATA`、库存规划报告。

## 6.7 采购订单 `/app/purchase-orders`

**列表筛选**：状态、供应商、预计到货日期、币种、采购金额、付款状态、收货进度、关联补货批次。

**详情** `/app/purchase-orders/:id`

- **状态步骤条**：草稿 → 待审批 → 已下单 → 生产中 → 部分到货 → 全部到货 → 已关闭。异常分支：取消、退货给供应商。
- **9 个页签**：
  1. 基本信息；
  2. 商品行：成本、关联补货批次、关联入仓计划；
  3. 审批：流程、审批人、意见；
  4. 付款：计划付款与实际付款、付款方式、凭证；
  5. 收货进度：分批收货；
  6. 质检：抽检比例、不良率、处理方式；
  7. 附件；
  8. 关联：补货批次、入仓计划、头程单；
  9. 操作记录。

**先进能力**：
- 交期偏差预警：预计到货日晚于补货需要日期时提醒；
- 成本差异：采购单价与当前成本版本不一致时提示；
- 收货完成后自动生成成本版本草稿。

**动作**：提交审批、审批、登记收货、登记质检、登记付款、上传附件。需要相应权限，多人编辑时做冲突检测，每一步写审计。

## 6.11 入仓计划 `/app/supply-chain`

**定位**：按入仓接口 `v2024-03-20` 的完整流程管理发往亚马逊物流的货件。

**页面结构**：计划列表、状态看板、异常队列（方案即将过期、操作失败、接收差异）。

**状态链**：

> 草稿 → 资格预检 → 入仓计划已创建 → 装箱方案已确认 → 箱内物品信息已提交 → 分仓方案已确认 → 运输方案已确认（含送达时间窗） → 标签已打印 → 已发货 → 运营中心接收中 → 差异处理中 → 已完结
>
> 另有取消分支：仅在作废窗口内可取消。
>
> 说明："已发货"是我方状态链上的标记（`POST /inbound/plans/:id/confirm`），入仓接口没有"发货"操作，该步骤不调用亚马逊。

**创建计划**：
- 支持多 SKU；
- 来源：补货批次、手工、采购单；
- 填写发货地址；
- 预处理方与贴标方固定为卖家（美国站 2026 年 1 月 1 日起）；
- 发货前调用入仓资格接口做预检。

**详情** `/app/supply-chain/:id`，共 11 个页签：

1. **概览**：步骤条；当前步骤需要的动作；截止时间，包括分仓方案过期时间与作废窗口剩余时间（倒计时）。
2. **商品**：SKU、数量、预处理要求、标签要求、资格预检结果。
3. **装箱方案**：各方案的装箱组、费用、折扣、运输模式、过期时间对比，选择后确认。
4. **箱内物品**：每箱的 SKU 与数量、尺寸、重量；支持批量导入与校验。
5. **分仓方案**：
   - 对比表：目的运营中心数、货件数、分仓服务费、折扣、过期时间；
   - 系统叠加计算总成本：分仓费 + 预估运费 + 到仓时效差带来的断货风险成本，按总成本最低给出推荐，而不只是看分仓费。
6. **运输方案**：合作承运与非合作承运、报价、送达时间窗，选择后确认。
7. **货件**：每个货件的目的运营中心、箱数、件数、状态、追踪号。
8. **标签**：箱标签、FNSKU 标签，支持批量打印。
9. **时间线**：所有异步操作及其状态、操作人。
10. **接收与差异**：按货件显示接收数量与差异。
11. **费用**：分仓费、入仓配置费、运费，以及卖家自理的预处理与贴标成本（录入）。

**动作**：每一步的确认与提交都受写入开关控制，先预览再执行，并写审计。所有写操作是异步的，界面展示操作状态，直到亚马逊返回结果。取消时提示作废窗口：小包裹在确认后 24 小时内，零担与整车在确认后 1 小时内。

**数据来源**：`Fulfillment Inbound API v2024-03-20`、`FBA Inbound Eligibility API`、`GET_FBA_FULFILLMENT_INBOUND_NONCOMPLIANCE_DATA`。

## 6.12 货件接收与差异 `/app/warehouse`

**列表字段**：货件编号、目的运营中心、货件状态、应发数量、已接收数量、差异数量、运输状态、追踪号、首次接收时间、接收完成时间、差异天数、赔付状态、不合规问题数。

**详情** `/app/warehouse/:shipmentId`：
- 接收时间线：发货、承运节点、签收、开始接收、接收完成；
- SKU 差异表：应发、已收、差异、差异原因；
