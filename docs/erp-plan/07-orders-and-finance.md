# 07 板块详设：订单与售后、财务

---

## 7.1 订单 `/app/orders`

**定位**：只看亚马逊物流订单，不出现自发货的待发货、分配履约人、内部时效等概念。数据基于订单接口新版。

**列表字段**：订单号、下单时间、店铺、订单金额、件数、订单状态、履约状态、配送承诺（最早、最晚送达）、承运商、追踪号、退款状态、关联退货、关联结算（递延、已释放）、净收益（我方计算）、风险标记。

**筛选**：状态、日期、ASIN、SKU、是否退款、是否退货、是否替换订单、是否使用促销、结算状态、风险标记。

**订单详情** `/app/orders/:id`

- **身份区**：订单号、下单时间、店铺、销售渠道、订单项目标记、订单状态、履约状态、订单金额、净收益。
- **9 个页签**：
  1. **概览**：订单头；配送承诺及计算依据（承诺计算所用的承运商信息）；关键时间点。
  2. **订单行**：商品、数量、单价、促销、税；取消信息，包括由谁执行、原因；关联商品，例如保修。
  3. **收入与费用**：
     - 收入明细：按商品、运费、税、礼品包装、促销拆分；
     - 费用：佣金、配送费等；
     - 净收益；
     - 与财务交易的匹配情况。
  4. **履约与包裹**：包裹列表、承运商、追踪号、物流节点、送达时间。
  5. **退款与退货**：退款记录、关联退货（可跳转）、替换订单。
  6. **财务交易**：该订单的全部交易，含状态（递延、已释放、递延后释放）与所属结算单。
  7. **买家信息**：默认掩码。查看时需填写理由，按角色授权访问，每次查看写审计；页面提示到期自动删除时间。
  8. **时间线**：我方记录的订单状态历史与推送事件。
  9. **风险标记**：取消请求、退款、退货、替换、税务异常、财务差异，每条带原因。

**数据来源**：
- `Orders API v2026-01-01`，`includedData` 取买家、收货、履约、收入、费用、促销、取消、包裹、税、付款；
- `GET_AMAZON_FULFILLED_SHIPMENTS_DATA_GENERAL`；
- `GET_FBA_FULFILLMENT_CUSTOMER_SHIPMENT_REPLACEMENT_DATA`；
- `Finances API v2024-06-19` 的 `listTransactions`，按订单编号过滤；
- 推送 `ORDER_CHANGE`。

买家个人信息只在服务端加密存储，到期删除，永不进入日志、导出、智能问答。

## 7.2 退货 `/app/returns`

**列表字段**：订单号、退货日期、ASIN、SKU、数量、退货原因、处置状态（可售、不可售、损坏、承运人损坏等）、运营中心、退货件编号、退款金额、是否已退款、退款后是否已收到退货、赔付状态。

**详情** `/app/returns/:id`：
- 订单与商品；
- 退货原因、买家备注（按非个人信息处理，可隐藏）；
- 处置状态；
- 退款、相关费用；
- 可售或不可售；
- 关联赔付；
- 处理时间线。

**分析视图**：按 ASIN、原因看退货率趋势，与评论主题交叉分析（见 05 章 5.7）。

**数据来源**：`GET_FBA_FULFILLMENT_CUSTOMER_RETURNS_DATA`、财务交易、客户反馈接口类目退货主题。

## 7.3 赔付中心 `/app/reimbursements`

**定位**：把"该拿回的钱"系统化。头部工具已有自动收入恢复，本页做到：机会自动识别、证据包自动生成、到账自动匹配、亚马逊支持案件状态自动同步。

**6 个页签**：赔付机会、待提交、处理中、已到账、已拒绝、全部案件。

**机会识别规则**（我方计算，时限按亚马逊当期政策在设置中配置）：

| 编号 | 机会类型 | 识别依据 |
|---|---|---|
| 1 | 入仓差异 | 接收数量少于应发数量，且超过等待期 |
| 2 | 仓内丢失 | 台账出现丢失调整，规定期内未找到也未赔付 |
| 3 | 仓内损坏 | 台账出现损坏调整，且未赔付 |
| 4 | 退款未退货 | 退款后超过规定天数仍未收到退货，也未自动赔付 |
| 5 | 退货处置异常 | 退货被判为不可售，但原因属于承运人或仓库 |
| 6 | 费用多收 | 来自费用核查结果 |
| 7 | 移除丢失 | 移除订单已关闭，但请求数量大于"已发货 + 已弃置" |

**每条机会包含**：规则、证据（可跳转到台账、货件、订单、报告原始行）、估算金额、申请截止时间、状态。

**赔付案件详情** `/app/reimbursements/:id`（独立对象）：
- 状态步骤：机会 → 已提交 → 处理中 → 已批准、部分批准或拒绝 → 已到账；
- 负责人；
- 应收金额，以及实收金额（由赔付报告与财务交易自动匹配）；
- 证据清单；
- 关联对象；
- 关联的亚马逊支持案件：状态与沟通记录自动同步（只读）；
- 时间线、评论。

**动作**：
- 生成案件；
- 一键导出证据包：差异计算、货件信息、签收证明等；
- 回填亚马逊案件编号：卖家支持接口只能读取，不能创建案件，因此提交需在卖家后台完成，再把案件编号回填到系统。

以上动作写审计。

**先进能力**：统计回收率、平均到账时长、各类机会的成功率。

**数据来源**：`GET_FBA_REIMBURSEMENTS_DATA`（落 `ReimbursementRecord`，与案件匹配后回写实收金额）、库存台账、货件接收、退货、费用核查、财务交易、`Support API v2025-02-01`。

## 7.4 支持案件 `/app/support-cases`

**列表字段**：案件编号、主题、状态、创建时间、最近更新时间、关联对象（赔付案件、货件、商品）。

**详情**：案件信息、沟通历史、预约回电、附件、关联对象。

**性质**：只读同步，所有修改在卖家后台进行。

**数据来源**：`Support API v2025-02-01`（`listCases`、`getCase`、`listContacts`），需要受限角色。

## 7.5 费用事件 `/app/finance`

**9 个页签**：配送费、佣金、仓储费、库龄附加费、入仓配置费、移除与弃置费、退款、赔付、其他调整。

**字段**：类型、子类型、金额、币种、发生时间、交易状态（递延、已释放）、关联对象（结算单、订单、ASIN、SKU、货件）、对账状态、来源（财务接口交易流水或结算报告）。

**动作**：标记差异、填写对账备注、查看证据、发起导出任务。

**数据来源**：`Finances API v2024-06-19`、`GET_V2_SETTLEMENT_REPORT_DATA_FLAT_FILE_V2`、各费用报告；推送 `TRANSACTION_UPDATE`。

## 7.6 费用核查 `/app/finance/fee-audit`

**4 类核查**：

1. **配送费**：按尺寸分段与重量核对。比较我方商品尺寸、亚马逊测量尺寸与费用预估报告，发现分段错误。
2. **佣金**：按佣金预览报告核对类目费率。
3. **仓储费**：按体积核对。
4. **入仓配置费**：与所选分仓方案的费用核对。

**结果列表**：SKU、费用类型、应收、实收、差额、依据、发生次数、累计差额。可一键转为赔付机会。

**先进能力**：追踪亚马逊重新测量导致的尺寸分段变化，在变化当天发出预警。

**数据来源**：`GET_FBA_ESTIMATED_FBA_FEES_TXT_DATA`、`GET_REFERRAL_FEE_PREVIEW_REPORT`、`Product Fees API`、单品经济数据中的费用属性（如尺寸分段）、费用事件。

## 7.7 结算交易 `/app/settlements`

**列表字段**：结算编号、周期、打款日、期初余额、本期收入、费用、退款、调整、打款金额、币种、交易数、对账状态、差异金额。

**详情** `/app/settlements/:id`：
- **汇总**：收入、费用、退款、赔付、调整、保留金；
- **交易明细**（AG Grid）：每笔可关联到订单、ASIN、费用事件；
- **三方核对**：结算报告、财务接口交易、我方订单三者比对；
- **异常清单**：未匹配的交易、金额不一致的交易；
- **打款记录**。

## 7.8 回款与现金流 `/app/finance/cashflow`

**内容**：
- **余额**：各账户余额；
- **递延与释放**：递延中的金额、预计释放日、已释放金额；
- **打款预测**：下次结算的打款日与金额估算；
- **按周现金流预测**：预计回款 − 采购付款计划 − 头程付款 − 广告扣款，标注为模型估算；
- **打款记录与到账核对**：到账为手工登记。

**数据来源**：`listBalances`、`listTransactions`（含交易状态）、结算报告、采购付款计划、头程费用。

## 7.9 利润分析 `/app/profit`

**定位**：真实核算的利润中心。

**对标与超越**：头部 ERP 已有按日周月及订单维度的利润、三种存货计价、费用分摊、货损计入、结账封存、延迟结算回款预测、与后台交易报表的公式核对。本页增加：
- 与亚马逊官方单品经济的自动双源核对；
- 可追溯的利润桥；
- 数据质量标记；
- 三种收入确认口径并存；
- 未来费用预览。

**口径设置**（企业级，带版本）：
- **收入确认口径**：下单口径、发货口径、结算释放口径，三种并存，可切换查看；
- **存货计价**：先进先出、移动加权、月末加权；
- **广告分摊规则**：先按广告商品报表归属到 ASIN，剩余的账户级花费按销售额或销量分摊；
- **店铺级费用分摊规则**：例如订阅费，按销售额分摊；
- **汇率规则**：交易日汇率，缺失时回退并标记。

**7 个页签**

1. **总览**
   - 净利润、利润率；
   - 利润桥瀑布：销售额 → 退款 → 平台费用（佣金、配送费、仓储费、库龄附加费、入仓配置费、其他）→ 促销费用 → 广告 → 采购成本 → 头程 → 关税 → 其他成本 → 赔付收入 → 汇兑损益 → 净利润；
   - 利润趋势；
   - 数据质量标记汇总。
2. **店铺利润**：按店铺展示利润与利润桥。
3. **ASIN 利润**：按 ASIN、SKU、父体展示单位经济；每行可展开与官方净收益对照。
4. **广告利润**：广告分摊后各 ASIN 的利润；广告对利润是拉动还是拖累。
5. **成本覆盖**：缺少成本的 SKU、成本版本过期、广告未分摊金额、汇率缺失或回退。
6. **利润桥对比**：任选两期，按项目分解利润变化。
7. **期间关账**：跳转到 7.12。

**每个金额同时显示**：原币金额、折算金额、汇率、汇率来源。不允许跨币种直接相加。

**数据来源**：利润日表（由派生任务基于订单、财务交易、费用、广告、成本版本、汇率计算）、`analytics_economics_2024_03_15`。

## 7.10 官方经济数据对账 `/app/finance/economics`

**3 个页签**

1. **双源核对**：按 ASIN、日期列出两组数：
   - 官方：销售、费用分项、广告、卖家提供成本、净收益；
   - 我方：对应的计算数。

   每行给出差异，以及差异分类：成本口径、广告口径、时间口径、未解释。
2. **费用预览**：未来 120 天的费用变化及其对利润的影响。例如亚马逊年度费用调整生效前即可看到影响。
3. **情景模拟**：调用官方模拟，查看价格、发往上游仓储数量等动作对费用与净收益的影响。

**数据来源**：`analytics_economics_2024_03_15` 的 `economics`、`economicsPreview`、`economicsSimulation`。

## 7.12 期间关账 `/app/finance/periods`

**列表字段**：期间、状态（开放、关账中、已关账、重新开账）、关账人、关账时间。

**关账流程**（详情页 `/app/finance/periods/:id`）：

1. **数据完整性检查清单**：
   - 各数据域同步完整；
   - 结算已到；
   - 成本覆盖率达标；
   - 汇率齐全；
   - 广告分摊完成；
   - 未处理的对账异常数为零或已确认。
2. **预览关账报表**。
3. **审批**。
4. **锁定**：对利润日表、汇率、成本版本做快照。

**重新开账**：需要更高权限并填写原因，写审计；重开后生成差异报告。
